# Transfer tools

Map a saved Portline profile with the shared bridge, then use the returned Dockline configuration or adapter. The operation contracts belong to Dockline; start with [the saved-site program](/guide/quick-start) for FileZilla-specific setup.

## Progress and bandwidth

Observe transferred bytes or impose a shared rate budget. See [Dockline: progress and bandwidth](https://h2ooooooo.github.io/dockline/guide/advanced-transfers#progress-and-bandwidth).

## Checksums

Compute a digest or compare content with an independently supplied expected digest. See [Dockline: checksums](https://h2ooooooo.github.io/dockline/guide/advanced-transfers#checksums).

## Publication and overwrite behavior

Stage a server destination, verify it and choose an explicit overwrite policy. Read this contract before relying on atomic replacement or retrying an uncertain rename. See [Dockline: publication and overwrite behavior](https://h2ooooooo.github.io/dockline/guide/advanced-transfers#publication-and-overwrite-behavior).

## Copy strategies

Copy between server paths using an explicitly supported strategy. A shared API does not imply server-native copy support. See [Dockline: copy strategies](https://h2ooooooo.github.io/dockline/guide/advanced-transfers#copy-strategies).

## Bounded traversal

Walk a server directory with depth and entry limits and inspect whether the inventory completed. See [Dockline: bounded traversal](https://h2ooooooo.github.io/dockline/guide/advanced-transfers#bounded-traversal).

## Capability discovery

Inspect adapter support and what is known about the server before choosing an optional operation. See [Dockline: capability discovery](https://h2ooooooo.github.io/dockline/guide/advanced-transfers#capability-discovery).
